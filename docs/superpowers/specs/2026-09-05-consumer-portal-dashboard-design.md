# Consumer Portal Dashboard Design

## 1. Overview
The Consumer Portal Dashboard provides webhook consumers with a centralized monitoring interface to track delivery performance, view event traffic trends, identify failures, and assess the operational health of their webhook endpoints.

## 2. Architecture & Data Flow

### 2.1 Routing & Controller
- **Route:** `GET /ui/consumers/dashboard`
- **Pipeline:** `:browser`, `:fetch_current_scope_for_consumer`
- **Controller:** `WhooksWeb.UI.Consumer.HomeController`
- **Inertia Page:** `consumers/portal/dashboard`

### 2.2 Parameters & Filtering
- `last`: Time range string (`"24h"` default, `"7d"`, `"30d"`).
- `project_id`: Optional UUID string to filter stats by a specific project.
- `interval`: Inferred automatically from `last` (`"hour"` for `"24h"`, `"day"` for `"7d"` and `"30d"`).

### 2.3 Inertia Props
- **Immediate Props (fast initial response):**
  - `projects`: List of available projects in the consumer's organization for the project filter dropdown.
  - `filters`: Current filter parameters (`%{last: last, project_id: project_id}`).
- **Deferred Props (`inertia_defer`):**
  - `kpis`:
    - `total_events`: Integer count of events for the consumer in the given time window.
    - `successful_events`: Integer count of successfully delivered events (`status: "delivered"`).
    - `failed_events`: Integer count of failed deliveries (`status: "failed"`).
    - `success_rate`: Float percentage `(successful_events / total_events) * 100` (rounded to 1 decimal place; `100.0` if `total_events == 0`).
    - `active_endpoints_count`: Integer count of active endpoints for the consumer.
  - `events_metrics`:
    - Time-series aggregation generated by `Whooks.Metrics.EventStats.timeseries/1` with options `[consumer_id: consumer.id, project_id: project_id, last: last, interval: interval]`.
  - `recent_events`:
    - Top 8 recent events for the consumer (ordered by `inserted_at desc`), serialized with topic and delivery attempt summary.
  - `endpoint_health`:
    - Up to 5 registered endpoints for the consumer, including `url`, `status` (active / disabled), and subscription count.

### 2.4 Context Layer Queries (`Whooks.Metrics`)
- Add `consumer_kpis/2`:
  - Accepts `consumer_id` and options (`last`, `project_id`).
  - Aggregates event counts grouped by status from `Whooks.Events.Event` within `inserted_at >= start_dt`.
  - Queries `Whooks.Endpoints.Endpoint` to count active endpoints (`is_active == true` or default active state).

## 3. Frontend Specification (`assets/js/pages/consumers/portal/dashboard.svelte`)

### 3.1 Design System & Component Library
- Layout: `$layouts/portal.svelte`
- Components: Built with `shadcn-svelte` primitives (`Card`, `Select`, `Button`, `Skeleton`, `BadgeStatus`).
- Charts: LayerChart v2 / `shadcn-svelte` chart integration.
- Language/Framework: Svelte 5 runes (`$props()`, `$state()`, `$derived()`, `$effect()`).

### 3.2 Page Sections
1. **Header & Filter Toolbar:**
   - Title: "Dashboard" with subtext explaining the view.
   - Project Select Dropdown: "All Projects" option plus projects from `projects` prop.
   - Time Range Select: "Last 24 hours", "Last 7 days", "Last 30 days".
   - Filter changes trigger `router.reload({ data: { last, project_id }, only: ['kpis', 'events_metrics', 'recent_events'] })`.
2. **KPI Summary Cards (4 Cards):**
   - Wrapped in `<Deferred data={["kpis"]}>` with skeleton fallback cards.
   - Card 1: Total Deliveries (`ActivityIcon`, total event count).
   - Card 2: Success Rate (`CheckCircle2Icon`, percentage format, positive color indicator).
   - Card 3: Failed Deliveries (`AlertTriangleIcon`, count with subtle destructive badge if $> 0$).
   - Card 4: Active Endpoints (`CableIcon`, count of active endpoints).
3. **Delivery Performance Chart Card:**
   - Wrapped in `<Deferred data={["events_metrics"]}>` with skeleton fallback.
   - Bar/area timeseries chart showing delivery volume segmented by status over the selected interval.
4. **Bottom Split Section (`grid grid-cols-1 lg:grid-cols-3 gap-6`):**
   - **Recent Deliveries (Left - 2/3 width):**
     - Card header with "Recent Deliveries" and "View all events →" link to `/ui/consumers/events`.
     - Table or compact list with columns: Status (`BadgeStatus`), Topic, Event ID, and Time (`DateTimeDisplay`).
     - Clicking row navigates to `/ui/consumers/events/:id`.
     - Graceful empty state when no events exist.
   - **Endpoint Health (Right - 1/3 width):**
     - Card header with "Endpoints" and "+ Manage" link to `/ui/consumers/endpoints`.
     - List displaying endpoint URL (truncated monospace), active status pill, and subscription count.
     - Empty state with "+ Add Endpoint" button if none exist.
5. **Auto-Polling:**
   - `usePoll(10000)` from `@inertiajs/svelte` keeps the metrics, chart, and recent events automatically up to date.

## 4. Edge Cases & Error Handling
- **Zero Events / New Consumer:**
  - KPI cards show zeroes without division-by-zero errors.
  - Delivery chart shows an informative empty placeholder ("No webhook activity during this timeframe").
- **Zero Endpoints:**
  - Endpoint widget prompts the user to add an endpoint.
- **Unauthenticated / Expired Session:**
  - Standard redirect to consumer login via `AuthPlug.fetch_current_scope_for_consumer`.
- **Invalid Parameter Safeguards:**
  - Unrecognized `last` string safely falls back to `"24h"`.

- **Controller Test (`test/whooks_web/controllers/ui/consumer/home_controller_test.exs`):**
  - Verify `GET /ui/consumers/dashboard` returns 200 and renders `consumers/portal/dashboard` when consumer is authenticated.

  - Verify filtering by `last` and `project_id`.
- **Metrics Unit Test (`test/whooks/metrics_test.exs`):**
  - Verify `Whooks.Metrics.consumer_kpis/2` computes correct total, success, failure, and active endpoint counts.

### 5.2 Manual Verification
- Log in as a consumer via magic link token.
- Navigate to `/ui/consumers/dashboard`.
- Verify KPI cards, charts, recent events list, and endpoint status load cleanly with skeletons.
- Change time range and project filters and verify partial reloads update correctly.
